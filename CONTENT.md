# Adding subjects and chapters

Everything the app shows comes from `content/`. You never need to touch the code to add material.

```
content/
  manifest.json            ← list of subjects → sections → chapters (you edit this)
  index.json               ← generated by the build script (don't edit)
  pathology/
    cell-injury.json       ← one file per chapter
    ...
  pharmacology/            ← a new subject is just a new folder
    autonomic.json
```

## Add a chapter (3 steps)

1. Copy `content/_template.json` to `content/<subject>/<chapter-id>.json` and fill it in. The `"id"` inside the file must match the file name.
2. Add the chapter id to the right section in `content/manifest.json`.
3. Run the checker, then deploy:
   ```
   node scripts/build.mjs
   npx vercel@latest deploy --prod --yes
   ```
   The checker refuses to write `index.json` if anything is wrong (duplicate ids, missing answer, unknown heading, missing image) and tells you exactly which line.

## Add a subject

Add a block to `manifest.json`:

```json
{ "id": "pharmacology", "title": "Pharmacology", "book": "KD Tripathi",
  "sections": [ { "id": "general", "title": "General pharmacology", "chapters": ["pharmacokinetics"] } ] }
```

Create `content/pharmacology/pharmacokinetics.json`, run the build, deploy. A subject switcher appears in the sidebar as soon as there are two subjects. Each student's progress is stored per subject.

## Chapter format

| Field | What it is |
|---|---|
| `id`, `title` | Chapter id (matches file name) and display title |
| `competency` | e.g. `"PA4.1–4.4"` — shown under the title |
| `ref` | Source line shown under every explanation, e.g. `"Robbins Basic Pathology, ch. 3"` |
| `subtopics` | Competency headings: `[{ "id": "mediators", "title": "Chemical mediators" }]`. Insights score each heading separately. |
| `mcqs` | `{ id, sub, diff: easy|medium|hard, q, opts: [4 strings], ans: 0–3, exp, related: [..] }` — optional `img` (path) |
| `cards` | `{ id, sub, front, back }` — optional `img` |
| `specimens` | Museum jars (see `pathology/specimens.json`): `name, organ, group, images[], quizCrop [top%, bottom%], gross[], keyPoints[], viva[{q,a}], correction` |
| `images` | Micrographs (see `pathology/histology.json`): `slug, file, title, caption, topic, author, license, source` |

Spotter and histology questions and cards are generated automatically from `specimens` and `images`.

## Rules that keep progress safe

- **Never change an existing `id`.** Students' progress is keyed by `chapter:id`. Editing the text of a question or card is fine; changing its id makes it look new.
- Deleting a question removes it everywhere; students' history for it is simply ignored.
- Ids only need to be unique inside one chapter.
- Images go in `img/` and must use open licences or your own photos. Don't copy textbook figures.

## Quality bar for new content

Single best answer, four options of similar length, one unambiguous key, an explanation that says why the key is right and why the most tempting wrong option is wrong, and 2–3 "read next" topics. Have a second person (or a second AI pass) check every key against the textbook before publishing.
